Lesson 04 · Core syntax

Conditions and loops

Rust has if, for and while like JavaScript, plus two new tools: match, a much stronger switch, and loop, which can hand back a value. Most control flow in Rust also produces a value, so the ternary operator is gone.

You will learn

  • How if differs: no parentheses, required braces, no truthy values
  • How if and match return values, replacing ? :
  • How match replaces switch, and why it never forgets a case
  • The Rust versions of for...of, the classic for (let i...), while and do...while
  • Ranges, labeled loops, and a first look at if let and while let

if and else

The shape is the same as JavaScript, with two syntax changes. You drop the parentheses around the condition. You must always write curly braces, even for one line.

Parentheses around the condition still compile, but the compiler warns: "unnecessary parentheses around `if` condition". cargo fmt and Clippy push you toward the bare style.

Tip

Rust's == compares strings by content and works on any type that supports comparison, including your own structs once you add #[derive(PartialEq)]. There is no loose equality, so "1" == 1 is a compile error instead of true.

No truthy or falsy values

JavaScript treats 0, "", null, undefined and NaN as false in a condition. Rust does not. The condition must be a bool, and you write the test you mean.

JavaScript checkRust check
if (count)if count != 0
if (name) for a stringif !name.is_empty()
if (items.length)if !items.is_empty()
if (user) for something that may be missingif user.is_some(), or better, if let Some(user) = user
if (!user)if user.is_none()

This removes a whole family of bugs, like the classic if (price) that treats a real price of 0 as "no price".

if is an expression, so no ternary

Rust has no condition ? a : b operator. It does not need one. An if block produces a value, the same way a function body does (you saw this rule in lesson 3). The last expression of the branch that runs becomes the value.

match instead of switch

match compares a value against a list of patterns and runs the first arm that fits. It does the job of switch, with none of the sharp edges.

  • Each arm is pattern => expression, separated by commas.
  • There is no fallthrough and no break. Only one arm runs.
  • | means "or". It replaces stacked case lines.
  • _ matches anything. It plays the role of default.
  • An arm with several lines uses braces: 404 => { log(); retry(); }.

match gives back a value

Like if, a match is an expression. This replaces the common JavaScript pattern of declaring a let and assigning it in every case, or building a lookup object.

Matching strings

You can match on text too. If you hold a String, call .as_str() so the arms can be plain string literals.

The last arm shows a new trick. A plain name like other matches anything, like _, and also gives you the value under that name.

More patterns: ranges, guards and tuples

match patterns can do much more than compare against one value. These are the ones you will use most.

match never forgets a case

A switch without a default silently does nothing for values you did not list. A match must cover every possible value. If it does not, the program does not compile, and the error tells you which values are missing.

With numbers you usually just add a _ arm. The real power appears with enums in lesson 9. When you add a new variant to an enum, every match that forgot it becomes a compile error. The compiler gives you a to-do list of every place to update.

Mental model

TypeScript fans sometimes write const _exhaustive: never = value in a default case to force this check. Rust does it for every match, with no tricks.

Looping over a collection

for...of becomes for ... in. Careful: JavaScript's for...in loops over keys, but Rust's for ... in loops over values. Rust has only this one kind of for loop.

The & in &fruits matters. It means "loop over the items by borrowing them". Without it, the loop takes ownership of the whole vector and you cannot use fruits after the loop. Lesson 5 explains why.

Counting loops and ranges

Rust has no C-style for (let i = 0; i < n; i++). You loop over a range instead. 0..5 counts 0, 1, 2, 3, 4. The end is excluded, just like i < 5. Add = to include the end.

Trap

(5..0) is an empty range, not a countdown. It produces nothing. To count down, build the range upward and call .rev().

Ranges are values, not just loop syntax. You can store one (let r = 1..10;), check it ((1..10).contains(&x)), or use it to slice a list: &v[1..3].

Getting the index and the value

When you need the position too, JavaScript gives you forEach((item, i) => ...) or entries(). Rust has enumerate(). Note the order: the index comes first.

Tip

Prefer for x in &v or enumerate() over for i in 0..v.len() with v[i]. It is shorter, and Rust can skip the bounds check on each access, so it is often faster too.

while, and do-while with loop

while is the same as in JavaScript, minus the parentheses.

Trap

Rust has no ++ or -- operators. Write i += 1 and i -= 1.

There is no do...while. Use loop, which repeats forever until you break, and put the check at the end.

Use loop instead of while true. The compiler understands that loop runs at least once and only exits through break, which helps it check your code. Clippy even warns about while true.

loop can return a value

This one has no JavaScript match. break inside a loop can carry a value, and that value becomes the result of the whole loop. It is handy for retry logic and searches.

In Rust, result does not need to be mut or start empty. It gets its one value from the loop. Only loop supports this. for and while always produce (), because they might run zero times.

Labeled loops and continue

continue skips to the next round, as in JavaScript. To break out of an outer loop from an inner one, both languages use labels. In Rust a label starts with a single quote.

You can combine labels with values: break 'outer value; works when the outer loop is a loop.

Preview: if let and while let

Sometimes you care about one pattern only, and a full match with a _ => {} arm feels heavy. if let runs a block only when the value fits the pattern, and pulls the data out at the same time. You will use it most with Option, Rust's replacement for values that may be null. See lesson 10.

while let keeps looping as long as the pattern fits. A common use is draining a stack: pop() returns Some(item) until the vector is empty, then None, which ends the loop.

Check yourself

How do you write const x = ok ? "yes" : "no" in Rust?

let x = if ok { "yes" } else { "no" };. if is an expression, so it replaces the ternary.

Does if items.len() { ... } compile?

No. The condition must be a bool, and Rust has no truthy values. Write if !items.is_empty() or if items.len() > 0.

What numbers does for i in 2..5 print?

2, 3 and 4. The end of .. is excluded. Use 2..=5 to include 5.

Your match on a number fails with "non-exhaustive patterns". What is the usual fix?

Add a catch-all arm, _ => ..., or a named one like other => .... A match must handle every possible value.

How do you loop over a vector and still use it after the loop?

Loop over a reference: for x in &v. for x in v moves the vector into the loop, and it is gone afterwards.

Which loop can give back a value with break?

Only loop. Write let found = loop { ... break value; };.
