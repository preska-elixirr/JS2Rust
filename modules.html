Modules and packages

Cargo does the jobs of npm, package.json scripts, tsc and Jest in one tool. Modules work a bit like ES imports, with one surprise: a file is not part of your program until you declare it.

You will learn

  • How package.json maps to Cargo.toml, and how version ranges work
  • The Cargo commands that replace npm install, npm run and friends
  • How import and export become mod, use and pub
  • How to split code across files and folders, and re-export like a barrel index.ts
  • Workspaces, tests, and which crate replaces your favorite npm package

package.json becomes Cargo.toml

Every Rust project has a Cargo.toml file at its root. It plays the same role as package.json: name, version, and dependencies. The format is TOML instead of JSON. TOML has sections in square brackets and key = value lines.

  • edition picks the Rust language edition (2015, 2018, 2021, 2024). It is a bit like the target in tsconfig.json. New projects get the latest one automatically.
  • [dev-dependencies] works like devDependencies. Those crates are only available in tests, examples and benchmarks.
  • There is no scripts section. The common commands are built into Cargo. For custom tasks, people use a Makefile, a justfile, or a small Rust program.
  • Cargo.lock is the lock file, like package-lock.json. Commit it.

Tip

There is no node_modules folder in your project. Cargo downloads crates once into a shared cache in your home folder. Build output goes to target/, which you add to .gitignore. cargo new does that for you.

Version numbers and features

Both npm and Cargo use semantic versioning (major.minor.patch). The difference is the default. In npm, the caret ^ is something npm install adds. In Cargo, a plain version number already means caret.

Cargo.tomlSame as npmAccepts
serde = "1.0.200""^1.0.200"1.0.200 and up, below 2.0.0
serde = "1""^1"any 1.x.y
axum = "0.7""^0.7"0.7.x only. Below 1.0, the minor number counts as the major.
serde = "~1.0.200""~1.0.200"1.0.x patches only
serde = "=1.0.200""1.0.200"exactly this version

Trap

In npm, "1.0.200" without a caret pins an exact version. In Cargo, the same text allows any compatible 1.x update. Write "=1.0.200" when you really want an exact pin.

Features: optional parts of a crate

Many crates ship optional parts that you switch on with features. Code for a feature you did not turn on is not compiled at all, which keeps builds smaller and faster. npm has no real equivalent. The closest thing is installing an extra plugin package.

If a crate's docs show a macro or function that does not exist in your project, a missing feature is the usual reason. Check the crate's page on docs.rs for a "Feature flags" tab.

Finding crates

  • crates.io is the registry, like npmjs.com. Search there, and look at the download counts and the date of the last release.
  • docs.rs hosts the API docs for every crate on crates.io, built from the code itself. Every public function, struct and trait is listed with its exact signature. JavaScript has nothing this consistent.
  • Run cargo doc --open to build the same kind of docs for your own project and all its dependencies, offline.

import and export become mod, use and pub

In JavaScript, every file is a module, and everything is private until you export it. Rust has the same "private by default" rule. You make an item public with pub, and you bring it into scope with use.

To see the idea without files, here is a module written inline with mod:

JavaScriptRust
export function f()pub fn f()
import { f } from "./math"use crate::math::f;
import { a, b } from "./math"use crate::math::{a, b};
import { a as b } from "./math"use crate::math::a as b;
import * as math from "./math"use crate::math; then math::add()
import fs from "node:fs"use std::fs;
import express from "express"nothing needed, or use axum::Router;
export * from "./user"pub use user::*;
export defaultno equivalent. Everything has a name.

Mental model

use never loads anything. It only creates a shortcut name. You can always skip it and write the full path, like std::collections::HashMap::new(). Crates from Cargo.toml are available by name everywhere, with no import step.

Splitting code into files

Here is the big difference from JavaScript. Creating a file does not add it to your program. The parent module has to declare it with mod name;. Rust then looks for name.rs, or name/mod.rs, next to the parent.

Trap

You create src/utils.rs, write a function in it, and use crate::utils fails with "unresolved import". The file exists, but nobody declared it. Add mod utils; to main.rs (or lib.rs). The editor plugin rust-analyzer also warns you that the file is not part of the module tree.

Instead of routes/mod.rs, you can also write routes.rs next to the routes/ folder. Both styles work. Newer projects tend to use routes.rs, so your editor does not show ten tabs called mod.rs. Pick one per project.

Paths: crate, super and self

JavaScript imports use file paths like "./x" and "../x". Rust uses module paths with :: between the parts. Three keywords tell Rust where to start.

Rust pathStarts atLike in JS
crate::config::Configthe root of your crate (main.rs or lib.rs)a path alias like "@/config"
super::helpersthe parent module"../helpers"
self::helpersthe current module"./helpers"
std::fs, serde::Serializean external crate"node:fs", "zod"

Tip

Prefer crate:: paths in app code. They work the same from any file, so moving code around breaks fewer imports. Save super:: for tests and for modules that belong tightly to their parent.

Visibility: pub and its smaller versions

Everything is private by default. Private means "visible inside this module and its child modules". You can open things up step by step.

KeywordWho can use itClosest JS / TS idea
nothingthis module and its childrennot exported
pub(super)the parent module toonone
pub(crate)anywhere in this crate, not outside itexported from a file, but not from the package entry
pubeveryone, including other cratesexport from the package

Struct fields have their own visibility. A pub struct can still keep some fields private. This works like private in a TypeScript class, but the compiler enforces it at every use, not only in the type checker.

Because password_hash is private, code outside the module cannot build a User with User { ... } either. You provide a pub fn new(...) constructor instead. That is how Rust protects rules like "a user always has a valid hash".

Re-exports instead of barrel files

In TypeScript, an index.ts barrel file re-exports things so callers get a short import path. Rust does the same with pub use.

The inner modules user and post stay private. Outside code sees models::User but cannot reach models::user::User. You can reorganize the files later without breaking anyone's imports. Big crates use this all the time, which is why docs.rs shows short paths like tokio::spawn.

Binary and library crates

A crate is either a binary (a program you run) or a library (code other crates use). Cargo decides from the file name.

FileCrate typeCreate withLike in JS
src/main.rsbinary, must have fn main()cargo new my-appan app with a start script
src/lib.rslibrarycargo new --lib my-liba package with a main or exports field
src/bin/*.rsextra binariesadd the fileseveral entries in bin

A package can have both main.rs and lib.rs. This is a common pattern: put the real logic in the library and keep main.rs thin. The library takes the package name, with dashes turned into underscores.

With this split, integration tests (shown below) can call your library directly. In this layout, main.rs does not repeat the mod lines. The modules belong to the library.

Workspaces for monorepos

If you use npm, pnpm or Yarn workspaces for a monorepo, Cargo workspaces will feel familiar. One root Cargo.toml lists the member crates. They share one Cargo.lock and one target/ folder, so shared dependencies compile only once.

Tests are built in

In JavaScript you install Jest or Vitest. In Rust, the test runner is part of Cargo. Unit tests usually live at the bottom of the same file as the code, inside a tests module.

  • #[cfg(test)] means "only compile this module when running tests". It never ends up in your real program.
  • use super::*; pulls in everything from the parent module, including private functions. Rust lets you test private code directly.
  • #[test] marks a function as a test. A test passes if it returns without panicking.
Jest / VitestRust
describe("add", ...)mod add_tests { ... }
it("works", () => ...)#[test] fn works() { ... }
expect(a).toBe(b), toEqual(b)assert_eq!(a, b);
expect(a).not.toBe(b)assert_ne!(a, b);
expect(ok).toBe(true)assert!(ok);
expect(fn).toThrow()#[should_panic], or assert!(result.is_err());
it.skip(...)#[ignore]
vitest add (filter by name)cargo test add
async test#[tokio::test] async fn ...

assert! and friends accept an optional message, formatted like println!: assert!(age >= 18, "age was {age}");.

Integration tests

Files in a top-level tests/ folder are integration tests. Each file is compiled as a separate crate that uses your library from the outside, so it can only reach pub items. This needs a lib.rs.

Mental model

Rust's standard library is small on purpose. Random numbers, regex, dates and HTTP all live in crates. That surprises people, but those crates are as standard in practice as the built-ins are in Node. Do not hesitate to add them.

Check yourself

You created src/utils.rs, but use crate::utils; fails. Why?

Nobody declared the module. Add mod utils; to main.rs or lib.rs. A file is only part of the program once its parent declares it.

What versions does serde = "1.0.150" accept?

Any version from 1.0.150 up to, but not including, 2.0.0. A plain version in Cargo means the same as ^1.0.150 in npm. Use =1.0.150 to pin it exactly.

How do you make a function usable everywhere in your crate, but not by other crates?

Mark it pub(crate) fn ....

What replaces npm install -D vitest?

Nothing for the test runner, because cargo test is built in. For other dev-only crates, use cargo add --dev name.

Where do unit tests usually live in Rust?

At the bottom of the same file as the code, in a #[cfg(test)] mod tests { use super::*; ... } block. Integration tests go in the tests/ folder.

What is the Rust version of an index.ts barrel file?

pub use lines in the parent module, for example pub use user::User; in models/mod.rs.
