How your code runs

This is the biggest difference, and most of the other differences come from it. JavaScript is run by an engine (V8 in Chrome and Node). Rust is turned into a program that your computer runs directly.

The big differences

Keep these in the back of your head. Each one has a full lesson.

  • JS Types are optional

    TypeScript types are a layer on top. You can escape with any, and the types are gone at runtime.

    RS Types are the law

    Every value has one exact type. There is no any. The compiler infers a lot, so you write fewer types than you expect.

  • JS Mutable by default

    const stops reassignment, but you can still change what is inside an object or array.

    RS Immutable by default

    Nothing changes unless you write mut. That covers the fields and items inside the value too.

  • JS Garbage collector

    The engine frees memory "some time later" when nothing points to it. You never think about it.

    RS Ownership

    Every value has one owner. When the owner goes out of scope, Rust frees the value right there. Lesson 5 covers this.

  • JS null and undefined

    Any value can secretly be missing. "Cannot read properties of undefined" is the result.

    RS Option

    There is no null. A value that can be missing has the type Option<T>, and the compiler makes you handle the empty case.

  • JS throw and try / catch

    Any function can throw. You cannot see that from its type.

    RS Result

    Functions that can fail return Result<T, E>. The error is part of the return type, so you always know.

  • JS Built-in event loop

    async and fetch work out of the box in Node and the browser.

    RS Pick a runtime

    The language has async and await, but you add a runtime library (almost always tokio) to run them.

One piece of advice for week one

The Rust compiler will reject your code a lot at first. That is normal, and it is not you being bad at this. JavaScript lets you run broken code and find out later. Rust moves all of that pain to compile time.

Read the error messages to the end. They are long because they are useful. Most of them point at the exact spot and often say "help: consider doing X". In many cases X is the fix.
