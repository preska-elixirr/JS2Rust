Lesson 02 · Core syntax

Variables and types

Rust uses let like JavaScript, but the rules flip. Variables are locked by default, numbers come in many sizes, and you can reuse a name on purpose.

You will learn

  • Why Rust's let is closer to JavaScript's const
  • How mut works, and why it goes deeper than const
  • The number types (i32, u8, f64 and friends) and when to use each
  • Shadowing, constants, tuples, and converting between types

let in Rust is const in JS

In JavaScript you pick const when a variable never changes and let when it does. Rust has the same two choices, but the words are different. A plain let can never change. You add mut (short for mutable) to allow changes.

Note where the error happens. JavaScript crashes when that line runs. Rust refuses to build the program at all, so the bug never reaches a user.

mut goes all the way down

This is where Rust is stricter than const. In JavaScript, const only protects the variable. You can still change what is inside the array or object. In Rust, a value without mut is frozen completely, including its contents.

Mental model

Treat every Rust let as a deep Object.freeze. When you need to change something, you say so with mut. Rust code reads easier because the few mut keywords show you exactly where things change.

Tip

Rust needs semicolons. Every let line ends with ;. There is no automatic semicolon insertion like in JavaScript. In lesson 3 you will see that leaving one off sometimes has a meaning.

Type annotations look like TypeScript

Good news: Rust writes types the same way TypeScript does, with a colon after the name. Like TypeScript, Rust also infers the type when it can, so you leave most annotations out.

The last two lines show a real difference. TypeScript falls back to any when it cannot tell. Rust has no any. It looks at how you use the variable later and picks one fixed type. If it still cannot work it out, it asks you to write the type.

Trap

A variable's type never changes. In TypeScript you can widen a type with a union like string | number. Rust has no union shorthand for variables. You use an enum for that, which lesson 9 covers.

Numbers come in many sizes

JavaScript has one number type (a 64-bit float) plus bigint. Rust has a separate type for each size and each kind of number. The name tells you everything: the letter is the kind, the digits are the size in bits.

  • i means signed integer. It can be negative.
  • u means unsigned integer. It is zero or bigger.
  • f means float. It has a decimal point.

Rust never mixes number types for you

JavaScript happily adds an integer and a decimal, because both are the same number type. Rust refuses to add an i32 to an f64. You convert one side yourself with as.

Trap

7 / 2 is 3 in Rust, not 3.5. Two integers always give an integer, and Rust drops the remainder. Write 7.0 / 2.0 or convert with as f64 when you want decimals.

Overflow is a bug, not a surprise

A u8 holds at most 255. If you add 1 to 255, Rust stops the program with a panic in debug builds (the ones you run while developing). Release builds wrap around to 0 instead. When overflow can happen, use the methods that say what you want.

You will learn about None in lesson 10. For now, read it as "no value".

Writing number literals

Booleans and characters

bool works the same as in JavaScript: true or false. The difference is that Rust has no truthy or falsy values. An if needs a real bool.

Rust also has a char type for a single character. This is where quotes start to matter.

Trap

In Rust, single quotes and double quotes are not interchangeable. 'hello' is a compile error because a char holds one character. Always use double quotes for text.

Shadowing: reusing a name on purpose

JavaScript does not let you declare the same name twice in one scope. Rust does. A second let with the same name makes a brand new variable that hides the old one. This is called shadowing.

Shadowing is different from mut in two ways:

  • The new variable can have a different type. mut can only change the value, never the type.
  • Each variable stays immutable. You get a fresh value without opening the door to changes.

It is very common for "parse and clean up" steps, where you would otherwise end up with names like rawInput, trimmedInput and parsedInput.

Shadowing inside a block

A block is any pair of curly braces. A shadow inside a block disappears at the closing brace, and the old variable comes back.

Constants and statics

For values known before the program runs, like limits and config, use const. It must have a type, and the name is written in SCREAMING_SNAKE_CASE.

  • const can live outside any function, at the top of a file. let cannot.
  • The value must be computable at compile time. You cannot use the result of a normal function call or read a file.
  • pub works like export. Lesson 12 explains it.
  • There is also static, a global with one fixed memory address. You will rarely need it as a beginner. Use const.

Tuples: small fixed groups

In TypeScript you might type an array as [number, number] to hold a pair. Rust has a real tuple type for this, written with parentheses.

The empty tuple () has a name: the unit type. It means "nothing useful", much like void in TypeScript. A function that returns nothing returns ().

Converting between types

JavaScript converts types for you, sometimes when you do not want it to ("5" * 2 is 10). Rust never does. You convert on purpose, and a conversion that can fail gives you a value you must check.

Mental model

as is a blunt tool. It never fails, so it can lose data: 300 as u8 gives 44. Use as for widening (small to big) and for int-float conversions. Use try_from when the value might not fit.

Naming and warnings

Rust has firm naming rules, and the compiler warns you when you break them.

ThingJavaScript styleRust style
Variables and functionsuserName, getUser()user_name, get_user()

Rust also warns about variables you never use. If you keep one on purpose, start its name with an underscore.

Check yourself

Which Rust line matches JavaScript's let total = 0?

let mut total = 0;. JavaScript's let allows reassignment, so you need mut in Rust. Plain let total = 0; matches const.

What does let x = 10 / 4; give in Rust?

2. Both sides are integers, so the result is an integer and the remainder is dropped. Write 10.0 / 4.0 to get 2.5.

Why does let v = vec![1]; v.push(2); fail?

v is not declared with mut, and in Rust that freezes the contents too. Write let mut v = vec![1];.

What type should an index into a list have?

usize. Lengths and indexes are always usize, so using it avoids conversions.

Is let name = 'Ana'; valid Rust?

No. Single quotes make a char, which holds exactly one character. Use "Ana".
