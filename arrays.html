Lesson 07 · Data

Arrays, vectors, iterators

The JavaScript array does everything. Rust splits that job between fixed arrays, growable vectors and borrowed slices. Your map and filter skills carry over almost one to one.

You will learn

  • When to use a fixed array [T; N] and when to use a Vec<T>
  • Why v[10] crashes and how .get() avoids it
  • Slices, and the three ways to loop over a vector
  • map, filter, reduce, find and sorting, the Rust way
  • Why iterators do nothing until you call collect

Fixed arrays and vectors

JavaScript has one array type that can hold anything and grow forever. Rust has two list types. Both hold items of one single type.

  • Array, written [T; N]. Its length N is part of the type and never changes. It lives on the stack.
  • Vector, written Vec<T>. It can grow and shrink. Its items live on the heap. This is what you will use 95% of the time.

An array cannot grow. rgb.push(1) fails with "no method named `push` found for array `[u8; 3]`". Use arrays for data with a natural fixed size: RGB colors, coordinates, the days of the week. Use Vec for everything else.

Mental model

Vec<T> is your JavaScript array, minus the mixed types. When you need different kinds of items in one list, make an enum and store that. Lesson 9 shows how.

Adding and removing items

The method names are close to JavaScript. Remember the mut: without it, a Vec is frozen.

pop returns Some(value) or None, because the vector might be empty. JavaScript returns undefined and hopes you notice. Lesson 10 covers how to unpack an Option.

Tip

insert(0, x) and remove(0) shift every other item, so they are slow on big lists. The same is true of unshift and shift in JavaScript. If you add and remove at the front a lot, use a VecDeque, shown near the end of this page.

Reading by index: panic or Option

Square brackets work like in JavaScript, with one big difference. Reading past the end in JavaScript quietly gives undefined. In Rust it stops the program with a panic.

  • Use v[i] when you know the index is valid, for example inside a loop over 0..v.len().
  • Use v.get(i) when the index comes from outside (user input, another list). Handle the None.
  • Indexes are always usize. An i32 index does not compile. Convert with i as usize.
  • There are no negative indexes. Use last(), or v[v.len() - 1] if you know the list is not empty.

Trap

v.len() - 1 on an empty vector does not give -1. len() returns an unsigned usize, so subtracting 1 from 0 overflows and panics in debug builds. Check is_empty() first, or use last().

Slices: a view into part of a list

A slice, written &[T], borrows a range of items from an array or vector. Unlike JavaScript's slice(), it copies nothing. It is a pointer and a length, just like &str for strings.

Ranges use start..end, where end is not included, the same as JavaScript's slice. Write ..=end to include the end.

Take &[T] in function parameters

If a function only reads a list, make its parameter a slice. Then it accepts a &Vec, an array, or part of either.

Three ways to loop over a vector

In JavaScript, for...of always gives you the items and the array stays usable. In Rust you choose: borrow the items, borrow them to change them, or take the whole vector. This is ownership showing up in loops.

map, filter and reduce

In JavaScript, map and filter are methods on the array, and each one builds a new array right away. In Rust you first turn the vector into an iterator with .iter(), chain your steps, and finish with a step that produces a result, like .collect() or .sum().

Some notes on the new parts:

  • |n| n * 2 is a closure, Rust's arrow function. Lesson 3 covers it.
  • collect() needs to know what to build. Give the variable a type like Vec<i32>, or write .collect::<Vec<_>>(). The _ lets Rust fill in the item type.
  • fold is reduce with a start value. Rust also has reduce, which uses the first item as the start and returns an Option for empty lists.
  • sum(), product(), count(), min() and max() are built in.

The stars: * and **

.iter() hands out references (&i32), not values. filter then passes a reference to each item, so you get a reference to a reference (&&i32). Each * peels one layer off. Math operators like n * 10 work on a reference directly, but comparisons like n > 2 need both sides to be the same type.

Searching a list

Searches return an Option instead of undefined or -1. You cannot forget the "not found" case, because the type makes you handle it.

Why one star for position and two for find? find borrows each item to look at it, which adds a layer. position, any and all pass the item itself. With struct fields you rarely notice, because u.age unwraps references for you.

Sorting

Rust sorts in place, like JavaScript, so the vector must be mut. Unlike JavaScript, numbers sort as numbers.

Trap

JavaScript's sort() with no argument converts numbers to strings, so 100 sorts before 9. Rust's sort() uses the real ordering of the type. You only need a comparator to sort a different way.

A comparator in Rust returns an Ordering (Less, Equal or Greater) instead of a negative or positive number. a.cmp(b) builds one for you. sort_by_key is the shortcut when you sort by one field.

Floats need a special comparator

Floats have a strange value, NaN (not a number), which is not smaller, equal or bigger than anything. So Rust does not let you call sort() on a list of f64.

total_cmp gives every float a fixed place, NaN included, so it never panics. Prefer it.

Joining into text

Spread and concat

Rust has no spread operator. Pick the tool that matches what you want.

Destructuring with slice patterns

Array destructuring has a Rust version too. Because a vector's length is unknown at compile time, you use if let or match, which handle the case where the shape does not fit.

.. means "any number of items here", and rest @ .. gives those items a name. The compiler checks that your match covers every possible length. More on patterns in lesson 9.

Iterators are lazy

A chain like .iter().map(...) does not run anything by itself. It builds a recipe. The work happens only when a final step asks for results: collect, sum, count, find, for_each, or a for loop.

Laziness has a real upside. Each item goes through the whole chain before the next item starts, and the chain stops as soon as it has an answer. No temporary lists get built in between.

Mental model

A Rust iterator chain is like a JavaScript generator pipeline, not like array methods. Nothing flows until something at the end pulls. That is also why the compiler can turn these chains into code as fast as a hand-written loop.

Check yourself

What happens when you read v[5] from a vector of length 3?

The program panics with "index out of bounds". Use v.get(5) to get None instead.

How do you double every number in nums into a new Vec?

let doubled: Vec<i32> = nums.iter().map(|n| n * 2).collect();

Why does nums.iter().map(|n| n * 2); alone do nothing?

Iterators are lazy. Nothing runs until a final step like collect(), sum() or a for loop pulls the items through.

What is the difference between for x in &v and for x in v?

&v borrows the items, so v is still usable after the loop. Plain v moves the vector into the loop, and you cannot use it afterwards.

What does vec![10, 9, 1].sort() give, and how is that different from JavaScript?

[1, 9, 10]. Rust sorts numbers as numbers. JavaScript's default sort() compares them as text.

Which parameter type should a function use to read a list of numbers?

&[i32], a slice. It accepts a &Vec<i32>, an array, or part of either.
