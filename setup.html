Lesson 01 · Getting started

Setup and first program

You install one tool, create a project with one command, and run it with another. If you have used Node and npm, almost every step has a direct match.

You will learn

  • How to install Rust with rustup on Windows, macOS and Linux
  • How to set up VS Code so it shows errors while you type
  • What is inside a Rust project, compared to an npm project
  • How to print values with println!, eprintln! and dbg!
  • The Cargo commands that replace your npm scripts

Install Rust with rustup

In JavaScript you might use nvm to install and switch Node versions. Rust has the same kind of tool, called rustup. It installs the compiler (rustc), the build tool (cargo) and the standard library, and it keeps them up to date.

Windows

  1. Go to rustup.rs and download rustup-init.exe.
  2. Run it. If it says you need the Visual Studio C++ Build Tools, let it install them. Rust uses Microsoft's linker (the tool that glues compiled code into an .exe) on Windows.
  3. Pick the default option (1) when the installer asks.
  4. Close your terminal and open a new one, so it picks up the new PATH.

Check that it works

Open a new terminal and ask both tools for their version. Your numbers will be different. Any version means the install worked.

Trap

"command not found" or "'cargo' is not recognized" almost always means the terminal is older than the install. Close every terminal window, including the one inside VS Code, and open a fresh one.

Rust ships a new stable version every six weeks. Run rustup update now and then. Old code keeps compiling, because Rust takes backwards compatibility seriously.

Set up your editor

Use VS Code and install one extension: rust-analyzer. It is the official language server, the Rust version of the TypeScript service that powers your autocomplete and red squiggles.

  • It shows compiler errors as you type, so you rarely need to run a build to find them.
  • It shows inferred types as grey hints next to your variables. This helps a lot while you learn.
  • Hover over any function or type to read its docs.

Tip

Do not install the old extension called just "Rust". It is deprecated. You want "rust-analyzer" by The Rust Programming Language. Turn on "Format on Save" too. It runs rustfmt, which works like Prettier.

JetBrains users can use RustRover. Zed, Neovim and Helix all support rust-analyzer out of the box.

Create your first project

In Node you run npm init -y and then write an index.js yourself. Cargo creates the folder, the config file, a working Hello World and a git repo in one step.

cargo run did two things. It compiled your code into a program, then it ran that program. The first build of a project is slower. After that Cargo only rebuilds what changed.

Want a library instead of a program? cargo new mylib --lib creates src/lib.rs instead of src/main.rs. That is the Rust version of a package you publish to npm.

The edition line picks a set of language rules. Editions come out every few years (2015, 2018, 2021, 2024). New Cargo versions use the newest one. Crates from different editions work together, so you do not need to think about it as a beginner.

main is the entry point

A Node script runs from top to bottom. Any line at the top level of the file runs. Rust does not work that way. A program always starts by calling a function named main, and the top level of a file can only hold definitions (functions, structs, constants, imports).

  • fn declares a function, like function.
  • main takes no arguments and returns nothing. Command line arguments come from std::env::args() instead, the Rust version of process.argv.
  • The program ends when main returns. There is no event loop that keeps it alive.

Trap

Writing let x = 5; at the top of a file, outside any function, is a compile error. Use const for top-level values, as you saw in lesson 2.

Printing: println! vs console.log

println! is the everyday way to print a line. The ! means it is a macro, not a normal function. A macro is code that writes code at compile time. For now, read the ! as "special function" and move on.

The big difference from console.log: the first argument is always a format string. Each {} in it is a slot that the next argument fills. You can also write a variable name inside the braces, which looks a lot like a template literal.

Trap

println!(name) does not compile. The first argument must be a string literal. Write println!("{name}") or println!("{}", name).

Display vs Debug

console.log prints anything, including objects and arrays. Rust has two ways to print a value, and a type has to opt in to each one.

  • {} uses Display, the clean form for users. Numbers and strings have it. Lists and your own structs do not.
  • {:?} uses Debug, the developer form. Lists, options and most standard types have it.
  • {:#?} is Debug, pretty printed over several lines. It is the closest thing to console.log of a big object.

#[derive(Debug)] asks the compiler to write the Debug code for your struct. You will put it on almost every struct you write. Structs get their own page in lesson 8.

Need the text as a value instead of printing it? format! takes the same arguments and returns a String. It is your template literal: let msg = format!("{name} is {age}");. Lesson 6 covers strings in depth.

Debugging prints: eprintln! and dbg!

JavaScript has console.error for errors. Rust has eprintln!, which prints to stderr (the error stream) instead of stdout. Use it for errors and logs, so they do not mix with the real output of your program.

dbg! is a debugging gift with no exact JS match. It prints the file, the line, the code you passed in and its value. Then it returns the value, so you can wrap it around any expression without changing your code's behavior.

Tip

dbg! uses the Debug format, so it works on lists and on any struct with #[derive(Debug)]. Remove your dbg! calls before you commit, the same way you remove stray console.log lines.

Comments and doc comments

Normal comments are the same as in JavaScript. Doc comments use three slashes instead of the /** */ JSDoc style, and they support Markdown.

  • /// documents the item right below it. rust-analyzer shows it when you hover.
  • //! documents the whole file or crate. You put it at the top of lib.rs.
  • cargo doc --open turns your doc comments into a website, the same kind you see on docs.rs.
  • The code inside a doc example is a real test. In a library crate, cargo test runs it, so examples in docs never go stale.

Debug vs release builds

cargo build makes a debug build in target/debug/. It compiles fast, runs slower, and checks for number overflow. cargo build --release makes an optimized build in target/release/. It compiles slower and can run 10 to 100 times faster. Use debug while you work, and release when you measure speed or ship.

That file is the whole program. You can copy it to another machine with the same operating system and run it there. No Node install, no node_modules.

Mental model

cargo clippy is ESLint with a very good rule set already turned on. Run it often while you learn. Its suggestions teach you idiomatic Rust, and each one links to an explanation.

The edit, check, run loop

With Node you save the file and run it. With Rust there is a compile step in between, so a good loop looks like this:

  1. Write code. rust-analyzer underlines mistakes as you type.
  2. Run cargo check when you want the full list of errors. It skips making a program, so it is much faster than a build.
  3. Fix errors from the top. One early mistake often causes several errors below it.
  4. Run cargo run once it compiles.

No install? Use the Playground

The Rust Playground runs Rust in your browser. Paste any example from this guide inside a fn main() { } and press Run. It also has buttons for Clippy and rustfmt, and it can share a link to your code.

Tip

Many examples in this guide skip the fn main() { ... } wrapper to stay short. If you paste one and get an error about statements at the top level, wrap the code in fn main().

Check yourself

Which file is the Rust version of package.json?

Cargo.toml. It holds the package name, version and dependencies, written in TOML.

How do you print a list like vec![1, 2, 3]?

Use the Debug format: println!("{:?}", list). Plain {} does not work for lists, because they do not have a Display form.

What is the fastest command to see all compile errors?

cargo check. It runs the compiler's checks but skips making a program.

Why does let x = 5; at the top of main.rs fail?

The top level of a Rust file only holds definitions. Code runs inside fn main(). Use const X: i32 = 5; for a top-level value.

What does dbg!(a + b) return?

The value of a + b. It prints the file, line, expression and value to stderr, then hands the value back, so you can wrap it around code without changing what the code does.
