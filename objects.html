Lesson 08 · Data

Objects, structs, maps

JavaScript objects do two jobs. Sometimes they are records with known fields, and sometimes they are bags of keys. Rust splits these jobs: a struct for records, a HashMap for key-value bags.

You will learn

  • How a TypeScript interface and an object literal become a struct
  • How a class becomes a struct plus an impl block, and what &self means
  • How to print, copy, compare and destructure structs
  • How Map and Record<string, number> become HashMap

Objects become structs

In JavaScript you can write an object literal anywhere, with any fields. In TypeScript you usually describe its shape with an interface or type. Rust always wants the shape first. You declare a struct, then you create values of it.

The syntax is close. The rules are not:

  • You must set every field when you create a value. There is no "missing" field.
  • You cannot add a field later. user.nickname = "A" fails with error[E0609]: no field `nickname` on type `User`.
  • The struct name goes in front of the braces: User { ... }. That is how Rust knows the type.
  • Text fields are usually String, not &str, so the struct owns its text. Lesson 6 explains why.

Mental model

A struct is a TypeScript interface that also exists at runtime. The compiler knows the exact fields and their sizes, so a struct has no hidden key lookup. Reading user.age is as fast as reading a local variable.

Creating values in functions

The field init shorthand from JavaScript works the same way. If a variable has the same name as the field, write it once.

The Rust function has no return and no semicolon after the struct. The last expression in a function is its return value. Lesson 3 covers this.

Changing fields needs mut

You saw this in lesson 2. A const object in JavaScript still lets you change its fields. A Rust struct without mut is frozen. You cannot mark a single field as mutable. mut goes on the whole variable.

Copying with changes: spread vs struct update

In React you copy objects with changes all the time: { ...user, email }. Rust has the same idea, called struct update syntax. The ..other part must come last.

Trap

Spread in JavaScript copies. ..user in Rust moves the fields it takes. Here name is a String, so it moves into updated, and user.name is no longer usable. Using user as a whole now fails with "borrow of partially moved value: `user`". Fields that are cheap to copy, like age and active, are copied instead. If you need to keep the original, write ..user.clone(). Lesson 5 explains moves.

Printing, comparing and cloning with derive

console.log(user) prints any object. Rust does not know how to print your struct until you ask for it. Try it and you get an error.

The fix is one line above the struct: #[derive(Debug)]. A derive tells the compiler to write standard code for you. Then you print with {:?}, or {:#?} for the pretty multi-line version.

Classes become struct + impl

A JavaScript class bundles data and methods in one block. Rust keeps them apart. The struct holds the data. An impl block (short for implementation) holds the methods.

  • Rust has no constructor and no new keyword. fn new is a normal function. Everyone names it new by convention.
  • Self (capital S) means "the type this impl block is for". Here it is Counter.
  • self (small s) is like this, but you must list it as the first parameter, and you always write self.count.
  • Functions without self are called associated functions. They work like static methods. You call them with ::, as in Counter::new(5).
  • Methods with self are called with a dot, as in c.increment().

&self, &mut self and self

The first parameter says what the method does with the struct. This is how Rust knows, at compile time, which methods change things.

Tip

Rust has no getter or setter keywords. Write plain methods. The convention is fn count(&self) for a getter (no get_ prefix) and fn set_count(&mut self, value: i32) for a setter. You can also split methods across several impl blocks for the same struct.

Mental model

Struct fields are private by default. Code outside the module (roughly, outside the file) cannot read them. Add pub to a field or method to make it public, like TypeScript's public. Lesson 12 covers modules.

No inheritance: use composition

Rust has no extends. A struct cannot inherit fields or methods from another struct. You put one struct inside another instead, and forward the calls you need.

For shared behavior across different types, like "anything that can describe itself", Rust uses traits. They are close to TypeScript interfaces. Lesson 11 covers them. For "one of several kinds", like Dog | Cat, Rust uses enums, which lesson 9 covers.

Destructuring structs

Destructuring works much like in JavaScript, with one rule: you must write .. to say "I am ignoring the other fields".

The &user on the right means "look inside without taking it". Without the &, the String fields would move out of user.

Optional fields become Option

TypeScript has bio?: string and string | null. Rust has neither. A field that might be empty has the type Option<T>, and you still write it out when you create the struct.

Tip

With #[derive(Default)] you can skip the empty fields: Profile { name: "Ana".into(), ..Default::default() }. Every Option becomes None, numbers become 0, and strings become empty. Lesson 10 covers Option in depth.

Tuple structs and unit structs

Sometimes the field names add nothing. A tuple struct has a name but numbered fields. A unit struct has no fields at all.

A one-field tuple struct is called a newtype. It gives a plain value its own type, so you cannot mix it up with another value of the same shape. TypeScript developers fake this with "branded types". In Rust it is free and normal.

Key-value bags become HashMap

When the keys are not known ahead of time, like user IDs or words in a text, you use a Record<string, number> or a Map in TypeScript. In Rust you use HashMap from the standard library. It is not loaded by default, so you import it with use.

get returns an Option, because the key might not be there. To get a default like scores.get(k) ?? 0, write scores.get(k).copied().unwrap_or(0). The .copied() turns the &i32 reference into a plain i32.

Trap

scores["zed"] compiles, but it panics (crashes) if the key is missing. JavaScript gives you undefined instead. Use .get() unless you are sure the key exists.

Counting with the entry API

The "get, add one, set back" pattern is so common that HashMap has a shortcut for it. entry(key).or_insert(0) finds the slot, puts 0 there if it is empty, and hands you a mutable reference to the value.

The * at the start follows the reference to the number inside the map, so += 1 changes the stored value. You will see this pattern in almost every Rust codebase.

Building a map from a list

Order is random. Use BTreeMap for sorted keys.

A JavaScript Map remembers insertion order. A Rust HashMap does not keep any order, and the order can change from run to run. When you need the keys sorted, use BTreeMap. It has the same methods.

Dynamic objects and JSON

Sometimes you really do not know the shape, like a JSON response you only peek into. In TypeScript you would use any or unknown. Rust has the serde_json crate, whose Value type can hold any JSON.

The r#"..."# is a raw string. It lets you write quotes inside without escaping them. Value is handy for a quick look, but real Rust code describes the JSON with a struct and lets serde fill it in. Lesson 13 shows that with a real API call.

Check yourself

Why does let p = Point { x: 1, y: 2 }; p.x = 5; fail?

p is not mut. In Rust, mutability belongs to the whole variable, so every field is frozen. Write let mut p = ....

How do you print a struct while debugging?

Add #[derive(Debug)] above it, then use println!("{:?}", value), {:#?} for pretty output, or dbg!(&value).

What is the difference between fn len(&self) and fn into_parts(self)?

&self borrows the value, so the caller can keep using it. self takes ownership, so the value is used up after the call.

What does map.get("key") return on a HashMap<String, i32>?

Option<&i32>. It is Some(&value) if the key exists and None if it does not.

You need a map that prints its keys in alphabetical order. Which type do you use?

BTreeMap. A HashMap has no stable order.
