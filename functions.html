Lesson 03 · Core syntax

Functions and closures

Rust functions look like TypeScript functions with the types required. The surprises are small but important: the last line returns by itself, there are no default parameters, and closures use pipes instead of arrows.

You will learn

  • How to write a function with typed parameters and a return type
  • Why the last expression returns without return, and how one semicolon breaks that
  • What to do instead of default parameters and overloads
  • How closures compare to arrow functions, and what move means
  • How to pass functions around with impl Fn

Defining a function

You write fn instead of function. Parameter types use a colon, the same as TypeScript. The return type comes after an arrow -> instead of a colon.

  • Parameter types are always required. Rust never infers them for named functions, even when it could.
  • The return type is required too, unless the function returns nothing.
  • Function names use snake_case: get_user, not getUser.
  • Order does not matter. You can call a function that is defined further down the file, like a hoisted JS function declaration.

Mental model

The type annotations on a function are its contract. Inside the function Rust infers almost everything, but the signature must be spelled out so that callers and the compiler can check calls without reading the body.

Text parameters are usually &str (a borrowed piece of text) and text return values are usually String (text the caller owns). Why there are two string types is the subject of lesson 6. For now, copy the pattern.

The last expression is the return value

Look again at add. There is no return keyword and no semicolon after a + b. In Rust, the last expression in a block is the value of that block. For a function body, that value is what the function returns.

You can still write return n * n;. It works, and nothing is wrong with it. But idiomatic Rust leaves it off for the final value, and Clippy will suggest that you do too.

Statements vs expressions: the semicolon rule

This trips up every JavaScript developer once. In Rust, putting a semicolon after an expression turns it into a statement. A statement has no value. So adding a semicolon to the last line means the function returns nothing.

Notice the compiler tells you the exact fix. The () in the message is the unit type, Rust's "nothing" value. It shows up whenever something has no useful value.

Blocks are expressions too

The same rule works for any pair of curly braces, not only function bodies. A block runs its statements, then gives back its last expression. This lets you compute a value in a few steps without a helper function or a temporary let outside.

Early return

For leaving a function early, return works exactly as in JavaScript. Guard clauses look the same.

The usual style: return with a semicolon for early exits, and a bare expression for the final value.

No default parameters

Rust has no default parameter values and no optional parameters. Every call passes every argument. There are three common ways to get the same effect.

Option 1: an Option parameter

For one or two optional values, take an Option. The caller passes Some(value) or None. Lesson 10 covers Option in depth.

Option 2: two functions with clear names

Often the cleanest answer is a second function. The standard library does this a lot: Vec::new() and Vec::with_capacity(10), split and splitn.

Option 3: an options struct

For many settings, JavaScript passes an options object. Rust does the same with a struct, and the Default trait fills in the values you leave out. The ..Default::default() part works like ...defaults in an object spread.

No overloading either

TypeScript lets you write several signatures for one function name. Rust allows exactly one function per name in a scope. You give each version its own name, or use generics and traits (lesson 11) when the logic is truly the same for many types.

This feels like more typing at first. In practice the names make calls easier to read, because rect_area(3.0, 4.0) says what it does.

Functions that return nothing

Leave out the -> part entirely. The function then returns (), the unit type, which plays the role of void.

There is also a "never returns" type, written !. Functions that always crash or loop forever use it. panic! and std::process::exit are examples. TypeScript calls this never.

Closures vs arrow functions

A closure is an anonymous function you can store in a variable or pass to another function. It is Rust's arrow function. The parameters go between two pipes |...| instead of parentheses, and there is no arrow.

  • Closure parameter types are usually optional. Rust infers them from the first use.
  • A one-expression closure needs no braces, like a short arrow function.
  • A multi-line closure uses braces, and the last expression is its value. No return needed.
  • You can write a return type, but then braces are required: |a: i32, b: i32| -> i32 { a + b }.

You will use closures all the time with iterators, exactly where you use arrow functions with map and filter in JavaScript:

Trap

Once Rust infers a closure's parameter types, they are fixed. Calling let id = |x| x; first with a number and then with a string fails. A closure is not generic the way const id = (x) => x is in JavaScript.

Capturing variables

Like arrow functions, closures can use variables from the scope around them. This part feels very familiar.

The difference shows up when a closure changes a captured variable. Both the variable and the closure must be mut, because calling the closure changes something.

Mental model

While a closure that changes count is still in use, nothing else may touch count. Rust allows reading it again only after the last call to increment. This is the borrowing rule from lesson 5, applied to closures. It prevents the "who changed this variable?" bugs that shared state causes in JavaScript.

move closures

By default a closure borrows the variables it uses. It looks at them where they live. Writing move before the pipes makes the closure take ownership of them instead. You need this when the closure outlives the current scope, for example when it runs on another thread or is returned from a function.

In JavaScript the garbage collector keeps captured variables alive automatically. Rust has no garbage collector, so you decide: borrow (the default) or move. Without move here, the compiler stops you with error E0373, "closure may outlive the current function, but it borrows `name`", and suggests adding move.

Passing functions as arguments

In TypeScript you type a callback as (n: number) => number. In Rust you write impl Fn(i32) -> i32, which reads as "any function or closure that takes an i32 and returns an i32". Named functions and closures both fit.

Fn, FnMut and FnOnce

Rust sorts callbacks into three kinds, based on what they do with captured variables. The compiler picks the right kind for each closure automatically. You only choose one when you write a function that accepts a closure.

KindWhat the closure may doCan be calledUse it when
Fnonly read captured variablesmany timesthe callback just computes something

Tip

Not sure which one to pick? Start with impl Fn. If the compiler complains that the closure changes something, switch to impl FnMut. The error message names the one you need.

Returning closures

Function factories work the same way. Return type impl Fn(i32) -> i32, and use move so the closure takes the captured value with it.

impl Fn works when the function always returns the same closure. If different branches return different closures, wrap them in a box: Box<dyn Fn(i32) -> i32>. Lesson 11 explains what dyn means.

Nested functions and recursion

You can define a function inside another function. Unlike in JavaScript, an inner fn cannot see the outer function's variables. Use a closure when you need that.

Recursion works as you expect. Rust does not promise tail call optimization, so very deep recursion can overflow the stack, the same as in JavaScript. A loop is the safe choice for large inputs.

Coming later: generics and methods

Two more function features get their own lessons. Here is a first look so they do not surprise you.

Generic functions

Generics look like TypeScript generics. The difference is the T: PartialOrd + Copy part, which says what T must be able to do. Here, "can be compared with >" and "can be copied". Those requirements are called trait bounds. See lesson 11.

Methods

Methods are functions inside an impl block. The first parameter, &self, is Rust's this, written out on purpose. See lesson 8.

Check yourself

Why does this fail? fn double(n: i32) -> i32 { n * 2; }

The semicolon turns n * 2 into a statement, so the body has no final value and returns (). Remove the semicolon: { n * 2 }.

How do you write (a, b) => a * b as a Rust closure?

|a, b| a * b. Add types if Rust cannot infer them: |a: i32, b: i32| a * b.

Rust has no default parameters. Name two ways to replace them.

An Option parameter with unwrap_or(default), a second function with a clear name, or an options struct that implements Default.

A function takes a callback that pushes items into a captured Vec. Which type do you write for the parameter?

impl FnMut(). Pushing changes the captured vector, so the closure is FnMut, not Fn.

When do you need move before a closure?

When the closure must outlive the scope it was made in, like closures sent to a thread or returned from a function. move makes the closure own the captured values instead of borrowing them.
