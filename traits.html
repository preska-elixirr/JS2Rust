Traits and generics

A trait is Rust's version of an interface. Generics look almost the same as in TypeScript. The big change is that a type only fits a trait when you say so out loud.

You will learn

  • How to turn a TypeScript interface into a trait and an impl block
  • Why Rust does not accept "it has the right shape" the way TypeScript does
  • Three ways to take a trait as a parameter, and when to use dyn
  • Generic functions and structs, and how T extends X becomes T: X
  • The standard traits you meet every day: Debug, Display, Clone, PartialEq and more

Interfaces become traits

In TypeScript, an interface lists the methods an object must have. A class then says implements. Rust splits this into three parts: the trait lists the methods, the struct holds the data, and an impl Trait for Type block connects them.

The trait only has signatures that end in ;. The bodies live in the impl block. &self plays the role of this. You saw it in lesson 8.

One struct can implement many traits, each in its own impl block. That keeps related methods together and makes each trait easy to find.

Shape is not enough: nominal typing

TypeScript uses structural typing. If an object has the right properties, it fits the interface, even if nobody ever mentioned the interface. Rust uses nominal typing. A type fits a trait only when an impl block says so. Having a method with the right name does not count.

The fix is one small block. After it, greet(&dog) compiles.

Mental model

In TypeScript, an interface is a description that many shapes happen to match. In Rust, a trait is a promise, and the impl block is you signing it. The compiler never guesses that two things are related.

A nice side effect: you can implement your own traits for types you did not write, even built-in ones like i32 or String. That is like adding a method to Number.prototype, but safe, because the method only exists where the trait is imported.

Trap

There is one limit, called the orphan rule. You cannot implement a trait from another crate for a type from another crate. For example, you cannot write impl Display for Vec<i32>, because both come from the standard library. Either the trait or the type must be yours.

Default methods

A trait can give a method a body. Every type that implements the trait gets that method for free and can still replace it. In TypeScript you would reach for an abstract class to get the same effect.

To override the default, write fn greet(&self) inside the impl block with your own body. Unlike a class, a type can pick up default methods from many traits at once. Rust has no class inheritance, so traits are how you share behavior.

Tip

struct English; is a struct with no fields. Its only value is English itself. It is handy when you need a type to hang trait methods on and have no data to store.

Traits as parameters

You want a function that takes "anything that is a Shape". TypeScript has one way to write that. Rust has three, and they mean almost the same thing.

Forms 1 and 2 compile to the same code. Use impl Shape when the function is simple. Use the generic form when two parameters must be the same type, or when you need to name the type again.

Where clauses for long bounds

When the bounds get long, the third form moves them after the signature with where. It changes nothing except readability.

T: Shape + Debug means T must implement both traits. It is the Rust spelling of TypeScript's T extends Shape & Debug.

Returning impl Trait

A function can also promise "I return some type that implements this trait" without naming the type. This is how you return closures and iterators, whose real type names are long or impossible to write.

Trap

-> impl Shape still means one single concrete type. The caller just does not get to see which one. You cannot return a Circle in one branch and a Square in the other. The compiler stops you with error[E0308]: `if` and `else` have incompatible types. The next section shows the fix.

Mixed lists with dyn Trait

In TypeScript, an array of Shape can hold circles and squares side by side. Rust can do this too, but you ask for it with dyn (short for dynamic). Each item goes in a Box, which stores the value on the heap and keeps only a pointer in the list.

Why the Box? A Vec needs every item to have the same size. A Circle and a Square have different sizes, but a pointer to either one is always the same size. JavaScript does this for you behind the scenes, because every object lives on the heap.

The same trick works for one shape and for return values:

Generic functions and structs

Generic syntax is nearly the same as TypeScript. Angle brackets after the name, then use T like any other type.

Note the impl<T> Stack<T>. The first <T> declares the type parameter. The second one uses it. Read it as "for every type T, here are the methods of Stack<T>".

Generics need bounds to do anything

This is the main difference from TypeScript. TypeScript lets you compare two values of any type with >. Rust knows nothing about T unless you add a bound, so even > fails.

Mental model

In Rust, == compares values, not references. Two users with the same fields are equal. If you want this in JavaScript you write a deep-equal helper. In Rust you add PartialEq to the derive list.

Tip

Start most data structs with #[derive(Debug, Clone, PartialEq)]. Debug alone saves you a lot of pain, because without it you cannot print the struct at all.

Display is your toString

JavaScript calls toString() when you put an object inside a template string. Rust calls the Display trait when you use {} in println! or format!. You cannot derive it, because only you know how your type should look to a human.

write! works like format!, but writes into the formatter f instead of building a new string. {:02} pads the number to two digits with zeros, like padStart(2, "0").

From and Into for conversions

When one of your types can turn into another, implement From. You then get .into() in the other direction for free. You have already used this: "Ana".into() turns a &str into a String through this trait.

struct Celsius(f64) is a tuple struct: a struct whose one field has no name. You reach the field with .0. It is a cheap way to give a plain number its own type, so you cannot mix up Celsius and Fahrenheit by accident.

Making your own iterator

In JavaScript, an object becomes iterable when it has a [Symbol.iterator] method, often a generator. In Rust, you implement the Iterator trait. It needs exactly one method, next, which returns Some(value) or None when it is done.

type Item = u32; is an associated type. It tells Rust what the iterator yields. It is like the T in TypeScript's Iterator<T>, but fixed by the type instead of passed in.

The best part: one next method unlocks every iterator method from lesson 7. You never write map or sum yourself.

Trap

Write for x in (Countdown { n: 3 }) with parentheses. Without them, Rust reads the { as the start of the loop body and gives a confusing error.

Operator overloading

JavaScript has no operator overloading. For a 2D point you would write p1.add(p2). In Rust, every operator is a trait in std::ops. Implement the trait and the operator works on your type.

What generics cost at runtime

In JavaScript, every method call looks up the method on the object at runtime. Rust lets you choose.

  • Generics and impl Trait. The compiler makes a separate copy of the function for each type you use it with. A call to print_area with a Circle and with a Square becomes two functions. This is called monomorphization. Calls are as fast as a normal function call, and the compiler can inline them. The cost is a slightly bigger program and longer builds.
  • dyn Trait. There is only one copy of the function. At runtime it follows a pointer to a small table of methods (the vtable) to find the right area. That lookup costs a tiny bit of time, about what JavaScript pays on every call.

Tip

Start with impl Trait or generics. Switch to dyn Trait when you need different types in one list, or a function that returns different types. The speed difference almost never matters in app code. Pick whatever makes the code simpler.

Check yourself

Your Dog struct has a name() method, but passing it where impl Named is expected fails. Why?

Rust uses nominal typing. Having a method with the right name is not enough. You must write impl Named for Dog { ... } so the compiler knows Dog fits the trait.

How do you make println!("{:?}", user) work?

Add #[derive(Debug)] above the struct. For {} without the :?, implement std::fmt::Display yourself.

What is the Rust version of T extends Shape & Debug?

T: Shape + Debug, either inside the angle brackets or in a where clause.

Can fn make(flag: bool) -> impl Shape return a Circle in one branch and a Square in the other?

No. impl Shape is one hidden type. Return Box<dyn Shape> and wrap each value in Box::new(...).

Which single method must you write to make your type an iterator?

fn next(&mut self) -> Option<Self::Item>, plus the line type Item = ...;. Every other iterator method comes for free.

Two User values with the same fields: is a == b true?

Yes, if User derives PartialEq. Rust's == compares values field by field. Without PartialEq, the code does not compile at all.
