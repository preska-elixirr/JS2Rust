Ownership quick rules

Full lesson: Ownership and borrowing. JavaScript has nothing like this, so here are the rules themselves.

  1. Every value has exactly one owner.
  2. When the owner goes out of scope, Rust frees the value.
  3. Assigning or passing a String, Vec or struct moves it. The old name can no longer be used.
  4. Numbers, bool, char and references are Copy. Assigning them copies, so the old name still works.
  5. &x borrows to read. You can have many at once.
  6. &mut x borrows to change. You can have only one at a time, and no readers while it exists.
  7. A reference can never outlive the value it points to.

Top 12 traps for JS developers

These catch almost everyone in the first weeks. When the compiler complains and you do not know why, check this list first.

  1. Single quotes are not strings. 'a' is a char. Write text in double quotes.
  2. Integer division drops the decimals. 7 / 2 is 3. Use floats when you want 3.5.
  3. let means frozen. Add mut to change a variable, push to a list, or set a field.
  4. Assignment moves. After let b = a; with a String or Vec, a is gone. Borrow with &a or call .clone().
  5. .len() counts bytes. "é".len() is 2. Use .chars().count() for characters.
  6. No s[0] on strings. Use s.chars().next() or s.chars().nth(i).
  7. No truthy or falsy. if items.len() does not compile. Write if !items.is_empty().
  8. Iterators are lazy. xs.iter().map(f) alone does nothing. Finish with .collect(), .sum() or a for loop.
  9. A semicolon changes the meaning. The last expression without ; is the return value. Add a ; and the function returns () instead.
  10. Out of range panics. xs[10] on a short list crashes instead of giving undefined. Use xs.get(10) when the index might be wrong.
  11. Futures do nothing until awaited. A forgotten .await means the request never happens. Also, reqwest does not treat a 404 as an error.
  12. unwrap() is a crash waiting to happen. It is fine in examples and tests. In real code, use ?, match or unwrap_or.
