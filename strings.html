Lesson 06 · The new idea

Strings

JavaScript has one string type. Rust has two: String, which owns its text, and &str, which borrows it. With lesson 5 behind you, this split makes sense.

You will learn

  • The difference between String and &str, and when to use each
  • How format! replaces template literals
  • Why len() counts bytes and why s[0] does not compile
  • The Rust names for every string method you use in JavaScript
  • Format specifiers, raw strings and multi-line strings

Two string types: String and &str

Remember the stack and heap from lesson 5. Rust's two string types follow the owner and borrower split.

  • String owns its text on the heap. It can grow and change. When its owner goes out of scope, the text is freed.
  • &str (say "string slice") is a borrowed view into text that someone else owns. It is a pointer plus a length. It cannot grow.

Mental model

String is to &str what Vec<T> is to &[T]. One owns a growable buffer, the other is a borrowed window into it. A string literal like "hi" is a window into text baked into your program file, so its type is &'static str.

Escape sequences match JavaScript: \n, \t, \", \\, and even \u{1F980} for a Unicode code point.

Template literals become format!

Rust has no backtick strings. You build text with the format! macro. It returns a new String. println! uses the same syntax but prints instead of returning.

Inside the braces you can write a plain variable name, like {name}. For anything else, use an empty {} and pass the expression after the string. The values fill the empty braces in order.

Trap

println!("{user.name}") does not compile. Inline names only work for plain variables, not field access, method calls or math. Write println!("{}", user.name) instead.

Joining strings

In JavaScript, + works on any two strings. In Rust, + needs an owned String on the left and a &str on the right, and it moves the left side. That surprises everyone. Most of the time format! or push_str is clearer.

len() counts bytes, not characters

Rust strings are always UTF-8. Plain English letters take one byte each, but many characters take two, three or four. len() returns the number of bytes. To count characters, use .chars().count().

JavaScript does not count characters either. It counts UTF-16 code units, which is why an emoji has length 2. Rust is just honest about it: len() is the size in memory, and characters are a separate question.

Tip

Use is_empty() to check for an empty string, not len() == 0. It reads better, and Clippy (the Rust linter) suggests it.

You cannot write s[0]

Because characters have different byte sizes, "the character at position 3" is not a simple lookup. Rust refuses to pretend it is. Indexing a string with a number does not compile.

These methods return an Option<char>, because the position might not exist. Lesson 10 covers Option. Also note that nth walks the string from the start, so it is slow on long text. If you need many lookups, collect the characters once: let chars: Vec<char> = s.chars().collect();

Slicing works on byte ranges

You can take a slice with a range, like &s[0..3]. The numbers are byte positions. If a position lands in the middle of a multi-byte character, the program panics.

Trap

Byte slicing works fine in your tests with English text and then panics on a user named "José". When you cut text by position, use .chars() with take and skip, or s.get(range), which returns None instead of crashing.

replace has the opposite meaning. In JavaScript, "a-b-c".replace("-", "+") gives "a+b-c". In Rust it gives "a+b+c". Use replacen(..., 1) to replace only the first match.

Chains read almost the same in both languages. The difference is the final collect(), which turns the lazy iterator into a list. Lesson 7 explains iterators.

Comparing strings

== compares the text, and you can compare a String with a &str directly. There is no === because there is no type juggling to guard against.

To match on a String, turn it into a &str with .as_str(). The patterns are string literals, which are &str, so both sides must be the same type. Lesson 4 covers match.

Functions should take &str

When a function only reads text, make the parameter &str. Then callers can pass a literal, a &String or a slice, and nobody has to give up ownership. Return a String when the function builds new text.

You can combine the parts: fill character, alignment, width, then precision. {:*^10.1} prints a number with one decimal, centered in 10 characters, padded with stars.

Tip

{:?} works for any type that has #[derive(Debug)]. Add that line above your own structs and you can print them while debugging. Lesson 8 shows it. There is also dbg!(x), which prints the file, line, expression and value, then hands the value back.

Raw strings and multi-line strings

Raw strings ignore backslash escapes. They are handy for Windows paths, regular expressions and JSON. Add # marks when the text itself contains double quotes.

Any Rust string literal can span several lines. The line breaks become part of the text. End a line with a backslash to join it with the next line, which also skips the next line's leading spaces.

Check yourself

What type is "hello" in Rust?

&'static str, usually just called &str. It is borrowed text stored inside the program. Call .to_string() to get an owned String.

What does "café".len() return?

5. The é takes two bytes in UTF-8, and len() counts bytes. "café".chars().count() returns 4.

How do you get the first character of a string?

s.chars().next(). It returns Option<char>, which is None for an empty string. s[0] does not compile.

Why does println!("{}", a) fail after let c = a + &b;?

+ takes the left String by value, so a moved into c. Use format!("{a}{b}") to keep both.

Which parameter type should fn greet(name: ???) use?

&str. It accepts literals, &String and slices, and the caller keeps ownership.

What does "a.b.c".replace(".", "/") return in Rust?

"a/b/c". Rust's replace replaces every match, like JavaScript's replaceAll.
