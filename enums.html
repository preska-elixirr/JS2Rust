Lesson 09 · Data

Enums and pattern matching

If you like TypeScript's discriminated unions, you will love Rust enums. They are the same idea built into the language, and the compiler checks every case for you.

You will learn

  • How a string literal union like "up" | "down" becomes an enum
  • How discriminated unions become enums whose variants carry data
  • Why match catches the case you forgot, with no never trick needed
  • The shortcuts: if let, let else, matches!, guards and @ bindings

String unions become enums

In TypeScript you often limit a value to a few strings. In Rust you list the options as variants of an enum. Variant names use PascalCase, and you write them with the enum name in front: Direction::Up.

A TypeScript union of strings is still a string at runtime. You can log it, compare it with ===, and send it as JSON. A Rust enum variant is not a string. If you want to print it, add #[derive(Debug)]. If you want ==, add #[derive(PartialEq)]. A typo like Direction::Upp fails at compile time, just like in TypeScript.

Tip

Most small enums start with #[derive(Debug, Clone, Copy, PartialEq)]. With Copy, passing a Direction to a function copies it instead of moving it, just like a number.

Discriminated unions become enums with data

This is where Rust enums get powerful. Each variant can carry its own data. In TypeScript you build this with a shared kind field. In Rust the variant itself is the tag, so you do not need a kind field.

Inside each match arm, the fields of that variant become variables. TypeScript does the same thing with narrowing: after case "circle", it knows s.radius exists. Rust gives you radius directly.

Three shapes of variant

A variant can have no data, named fields like a struct, or unnamed fields like a tuple. You can mix them in one enum.

Mental model

An enum value is exactly one of its variants at a time, together with that variant's data. It is a box with a label. The label says which variant it is. You must check the label before you can touch the data inside. match is how you check.

match checks every case

In TypeScript, a forgotten case is easy to miss. The usual safety net is a never check in the default branch, and you must remember to write it. In Rust, match must cover every variant. The check is always on.

This pays off when the code grows. Add a Triangle variant next month, and the compiler lists every match in the project that needs a new arm. Nothing slips through to production.

Trap

A catch-all arm _ => ... turns this check off for that match. New variants fall into the catch-all without a warning. Use _ when you really mean "everything else", not to make an error go away.

Methods on enums

Enums get impl blocks just like structs (see lesson 8). Inside, match self is the usual pattern. You can write Self::Circle instead of Shape::Circle.

{ .. } means "this variant, whatever its fields are". &'static str is a string that lives for the whole program, like a string literal. Lesson 6 explains it.

TypeScript numeric enums

TypeScript also has an enum keyword, mostly used for numbered codes. Rust can give variants explicit numbers too. The difference is that Rust never turns a number back into an enum for you.

To go from a number to a variant, you write the conversion yourself. The standard way is the TryFrom trait, because the number might not match any variant.

if let and let else

A full match is a lot of typing when you only care about one variant. if let is the shortcut. Read it as "if this value matches this pattern, then...".

let else for early returns

A common JavaScript style is the guard clause: check for the bad case, return early, then carry on with a narrowed value. let else does exactly that. If the pattern does not match, the else block runs, and it must leave the function (or loop) with return, break, continue or a panic.

Getting a bool with matches!

Sometimes you only want true or false: "is this a circle?". The matches! macro gives you that in one line. It is handy inside filter.

The if *radius > 10.0 part is a guard. The next section explains guards.

Patterns: guards, ranges, @ and nesting

Patterns can do much more than name a variant. Lesson 4 showed match on numbers. Here is the full toolbox.

Rust checks the arms from top to bottom and runs the first one that matches. There is no fall-through and no break.

Binding a value with @

name @ pattern checks the pattern and also keeps the value in a variable.

Nested patterns

Patterns nest as deep as your data. You can match a variant, a specific value inside it, and an Option inside that, all in one arm.

Mental model

In TypeScript the union protects you until someone writes as any or forgets a never check. In Rust there is no way around it. The posts exist only inside Success, so code that reads posts while loading cannot be written at all.

Check yourself

A TypeScript union uses a kind field as its tag. What plays that role in Rust?

The variant itself. Shape::Circle { radius } carries its own tag, so you never add a kind field.

You add a new variant to an enum. What happens to existing match expressions?

Every match that does not have a _ arm stops compiling with error E0004, and the error points to each one. You update them, and nothing is missed.

When do you use if let instead of match?

When you care about one pattern and want to ignore or else the rest. match is for handling several cases.

Why does if dir == Direction::Up fail on a fresh enum?

== needs the PartialEq trait. Add #[derive(PartialEq)], or use matches!(dir, Direction::Up).

What must the else block of a let else do?

Leave the current function or loop: return, break, continue, or panic. It cannot fall through, because the variable would have no value.
